# Платформа

Всё ниже — факты о том, где игра живёт и какие инструменты есть. Как делать
игру, решаешь ты вместе с автором.

## Репозиторий = сайт
- `index.html` в корне репозитория — это и есть игра. Сборки нет: что лежит в
  репозитории, то и отдаётся как статика.
- После `git add -A && git commit && git push` превью обновляется само за
  секунды. Превью и публикация видят только запушенное.
- В раздачу не попадают `.claude/`, скрытые файлы, `*.md`, `*.test.js`,
  `tests/`, `node_modules/`. Один файл ≤ 25 МБ, весь сайт ≤ 200 МБ.
- Бинарники (картинки, звуки, шрифты) в репозиторий не принимаются — им место
  в файлах проекта (ниже). Репозиторий — для кода и текстов.

## Ход и объём работы
- Один ход агента ограничен: 3 часа и 800 вызовов инструментов, под — 1 ядро и
  2 ГБ памяти (тяжёлые тесты и солверы упираются в них раньше таймаута).
- Один вызов инструмента ограничен лимитом вывода модели (~32 тыс. токенов,
  это ≈100 КБ кода): файл больше — записывается частями (`write_file` начала,
  затем дописывание), иначе вызов обрывается и не исполняется.
- Большой объём — десятки уровней, несколько игр, длинный контент — делается
  порциями: первая порция (например, 10 уровней) → commit, push, автор смотрит
  в превью → следующая порция отдельным ходом. Так автор видит результат рано,
  а срыв хода не теряет сделанное; всё разом за один ход теряется целиком.

## Бриф
Бриф проекта — файл `docs/brief.md` в репозитории. Кабинет показывает его
автору во вкладке «Бриф» (файлы `*.md` в раздачу сайта не попадают, но в git
живут).

## Публикация
- Инструмент `deploy` публикует текущий запушенный код новой версией.
  Необязательный параметр `name` — название игры в кабинете автора; без него
  берётся имя проекта (первая строка первого сообщения), согласованное в брифе
  название обычно точнее.
- Адрес игры назначает платформа, у автора его не спрашивают. `deploy`
  возвращает `url` (адрес игры), `pinned_url` (закреплённый адрес версии) и
  номер версии. Адрес между публикациями не меняется. У партнёрских брендов
  адрес в их домене — верен тот, что вернул инструмент.
- По адресу игры (вида `https://<домен игр>/<id>`) она открывается во весь экран
  внутри iframe оболочки. Сама игра живёт на своём поддомене (свой origin:
  `localStorage` и cookie только её).
- Игра открывается и как `/vN/…`, поэтому работают только относительные пути
  (`./main.js`, а не `/main.js`). Глубокие ссылки — через query или hash,
  оболочка пробрасывает их во фрейм. Fullscreen, геймпад, гироскоп и autoplay
  разрешены атрибутом `allow` фрейма; `postMessage` в `window.parent` доходит
  до оболочки; `SharedArrayBuffer` недоступен.
- Автор может опубликовать и сам кнопкой в кабинете. Версии и откат — там же;
  старые версии живут по закреплённым адресам, хранятся 10 последних.

## Файлы проекта
- `file_upload` — сохранить файл (по внешней `url`, списку `urls` до 30 штук
  или `path` из рабочего каталога, до 50 МБ) и получить постоянную прямую
  ссылку для кода.
- `file_list` — что уже сохранено, со ссылками. `file_delete` — удалить по id.

## Картинки
- `asset_generate` — генерация картинки. Поле `style` выбирает поставщика:
  `pixel` — пиксель-арт (герой 64/96/128 px, предмет 32/48/64, фон 180×320 с
  удвоением, бесшовные тайлы, честная прозрачность, лист кадров анимации из
  готового героя через `kind=sheet` + `source` + `action`); `image` — общая
  модель, любой стиль из `prompt`, от 1K, прозрачность у sprite/item/icon/ui
  вырезается платформой по цветному фону; `vector` — SVG для иконок и
  интерфейса. Виды (`kind`): sprite, item, icon, ui, background, tile, sheet.
  Цены в описании инструмента. Результат сразу в файлах проекта, в ответе
  ссылка и `body` — непрозрачная область картинки.
- `asset_search` — бесплатный каталог CC0 (Kenney, 7 936 картинок, прозрачные,
  один `pack` = один стиль), возвращает прямые ссылки.
- `image_search` — стоковые фото (Pexels), прямые ссылки.
- Графика кодом (canvas, шейдеры, процедурная генерация) всегда доступна и
  ничего не стоит.

## Вопросы автору
`ask_user` показывает вопрос с вариантами и позволяет приложить файлы; автор
может ответить и своим текстом.

## Библиотеки офлайн (`vendor/`)
Внешние CDN недоступны или медленны у части игроков, поэтому библиотеки лежат
в репозитории. Можно брать любую, несколько или ни одной.

| файл | что | версия |
|---|---|---|
| `vendor/phaser.min.js` | Phaser 3, полная сборка (Arcade + Matter) | 3.90 |
| `vendor/three.module.js` + `vendor/three.core.js` | three.js, ES-модуль (module импортирует core) | 0.186 |
| `vendor/three-addons/` | OrbitControls, GLTFLoader, postprocessing, shaders, utils | 0.186 |
| `vendor/pixi.min.js` | PixiJS 8 | 8.21 |
| `vendor/matter.min.js` | Matter.js, 2D-физика | 0.20 |
| `vendor/cannon-es.js` | cannon-es, 3D-физика, ES-модуль | 0.20 |
| `vendor/howler.min.js` | Howler, звук | 2.2 |

three.js и его аддоны — ES-модули, им нужна import map в `index.html`:
```html
<script type="importmap">
{"imports": {"three": "./vendor/three.module.js", "three/addons/": "./vendor/three-addons/"}}
</script>
<script type="module">
import * as THREE from "three";
import { OrbitControls } from "three/addons/OrbitControls.js";
</script>
```

## Что платформа умеет принять от игры (необязательно)
Игру могут открыть внутри чужой страницы через iframe с `?embed=1`. Если игра
шлёт родителю события, платформа их показывает:
```js
window.parent.postMessage({source: "zv-game", type: "ready"}, "*");
window.parent.postMessage({source: "zv-game", type: "start"}, "*");
window.parent.postMessage({source: "zv-game", type: "finish", score, won, meta}, "*");
```

## Где играют
Превью и готовую игру открывают в браузере, чаще всего с телефона.
